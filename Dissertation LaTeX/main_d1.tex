	\subsection{Skin Lesion Classification Models} \label{lit:models}
	A skin lesion classification model is a type of image classifier machine learning model trained on a skin lesions images dataset to identify the different types of skin lesions present in the dataset. The field of automated skin lesion classification has been greatly boosted this century by developments in machine learning. No single model or method is clearly superior so this section covers some recent popular and successful datasets and model architectures.

		\subsubsection{Popular Datasets}
		As learned from Heriot-Watt University forth year courses a surprising amount of a machine learning model's performance comes from proper analysis and handling of the training, validation and testing datasets. There are currently nearly 30 public skin lesions datasets available although not all are downloadable without requesting access (paid and free) \cite{survey_datasets_2021, survey_2023}. The most utilised datasets found in papers were Ham10000 \cite{ham_paper, ham_src} and from the International Skin Imaging Collaboration (ISIC) Archive \cite{isic_site}. ISIC  have a large collection of quality controlled datasets and host various ongoing competitions to allow researchers to test performance of their algorithms \cite{isic_site_challenge, isic_site}. Ham10000 served as a training dataset for the ISIC 2018 Challenge \cite{isic_2018_challenge} and has continued to be used to train machine learning models in many papers \cite{survey_2023, survey_general_2023}.

		\subsubsection{Recent High Performance Models}
		There are many papers on different skin lesion classification models which use unique techniques and model architectures. Not every model architecture is supported by the FPGA frameworks in \bcref{lit:fpga_pipelines} so the following models architectures were checked to have at least closely supported architectures. The objective of most papers is to achieve a higher model classification accuracy than existing solutions.
		\\
		Some papers have achieved higher overall model accuracy by combining multiple specialised machine learning models. A paper by \citet{gabor_2019} in 2019 uses Gabor filtering to split each image from the ISIC 2017 dataset \cite{isic_2017} into 7 frequency images for training 7 separate CNNs. An 8th CNN is trained on the original images to retain lesion colour and geometry. All the CNN's output probabilities are fused together to produce the final diagnosis \cite{gabor_2019}. The best configuration called I-GR0235 was chosen for a superior positive/negative response (AUC) of 96\% while still having good classification accuracy of 83\%. Another approach by \citet{hybrid_2025} in 2025 compared several combinations of merges of pre-trained networks to find the best merged model accuracy \cite{hybrid_2025}. The networks were evaluated using the ISIC 2018 dataset \cite{isic_2018} and the best model had an accuracy of 92.87\% from combining pre-trained ResNet-18 and MobileNet models. \citet{scdnet_2022} in 2022 proposed a model based on a pre-trained VGG16 model called SCDNet which was trained and tested on the ISIC 2019 dataset \cite{isic_2019}. The paper focuses on specialising model layers for image filtering and identifying features in the images \cite{scdnet_2022}. An accuracy of 96.91\% was achieved by the model.
		
		\smallskip\noindent
		Other papers focus on improving a single general model. The method proposed by \citet{wide_shufflenet_2022} in 2022 creates a mathematical algorithm EW-FCM to more heavily pre-process the datasets. Either the Ham10000 or ISIC 2019 datasets were used across 3 experiments. It uses less computation overhead than other NN based methods to remove background artifacts and crop to the region of interest. The images are then fed to their CNN model wide-ShuffleNet to classify 7 or 8 skin lesion types (Ham10000 has 7 while ISIC 2019 has 8) \cite{wide_shufflenet_2022}. The wide-ShuffleNet model is designed to be lightweight and efficient so it could run on a mobile system and is proved to have higher accuracy and efficiency than larger models it was compared with. The best accuracy was 86.33\% in experiment 2 using the Ham10000 dataset (90\% training, 10\% testing). A paper by \citet{skinlesnet_2023} in 2023 uses a modified version of the PAD-UFES-20 dataset \cite{padufes20} called PAD-UFES-20-Modified that contains smartphone photos rather dermoscopic images. The PAD-UFES-20 dataset has less than 1000 images (10 times smaller than Ham10000), 3 skin lesion classes and required more pre-processing than most datasets but means the proposed model is more suitably trained for clinical use. The model is a bespoke 4-layer CNN called SkinLesNet that learns a hierarchy of spatial features \cite{skinlesnet_2023}. The SkinLesNet model is compared against pre-trained VGG16 and ResNet50 models, benchmarked using the Ham10000 and ISIC 2017 datasets. The model achieves its highest accuracy of 96\% using PAD-UFES-20-Modified.

	\subsection{Mobile Hardware for Machine Learning Acceleration} \label{lit:hardware}
	Many options for portable hardware exist such as Raspberry Pi, mobile, embedded FPGAs, Nvidia AI accelerators. This section covers a few popular options including the PYNQ-Z1 which is used for this project.
	
		\subsubsection{Raspberry Pi 3}
		Raspberry Pi boards are designed as an embedded System on Chip (SoC) architecture however possess no specialised acceleration hardware beyond what is expected of a modern CPU. We are already familiar with the Raspberry Pi 3 \cite{pi3_product_page}. A cheap hardware package (around £30 at time of research) often used for running lightweight servers and connecting to a vast array of peripherals via a custom Linux operating system. Not known for high performance but has low power usage of only 1.5-4W according to \cite{tess_pi}. %[Section 6]

		\subsubsection{Mobile}
		Modern mobile phones have various sensors, cameras and processors designed for general purpose use. For this project only the phone's processor and any AI accelerators would be used so many of the features would be unutilised. This amounts to a larger cost to have access to processors that exist on cheaper and simpler embedded SoC boards.

		\subsubsection{PYNQ-Z1}
		The PYNQ-Z1 is part of a series manufactured by Xilinx designed to make running neural networks on FPGAs more easily accessible \cite{pynq_z1_man}. It is an embedded SoC architecture that has an ARM CPU which can run a Linux bootloader similar to a RPi and an embedded FPGA (Field Programmable Gate Array) chip which can be used to create specialised accelerator hardware. Both chips share system resources including RAM \cite[Section 2]{pynq_z1_man}. An FPGA can achieve higher speeds than most accelerators while being programmable, only requiring a few Watts and having limited hardware resources. The PYNQ-Z1 provides a base framework to allow using the FPGA without having to design physical logic circuits. Many frameworks exist to generate efficient and optimised logic circuits which is explored in \bcref{lit:fpga_pipelines}.

	\subsection{Machine Learning Models to FPGA Frameworks} \label{lit:fpga_pipelines}
	This section describes a few of the options for frameworks that could be used to run a skin lesion classification machine learning model on an FPGA.

		% Mentioned as an option but only an old version supports PYNQ-Z1
		\subsubsection{Vitis AI}
		Vitis is a software platform used for digital signal processing and machine learning. The Vitis AI framework is part of the platform and is designed for AI acceleration of CNN models \cite[Page 16, AI Engine Development Environment]{vitis_paper}. A variety of tools and optimisations are included for designing programmable logic focusing on better area compute density and reducing power consumption compared to traditional implementations. It abstracts the programming to C/C++ languages level to allow for easier porting between specific hardware. The current version of Vitis AI is 5.0. The Zynq-7000 family (includes PYNQ-Z1) lost support as of version 1.4 because they were considered to not have enough resources for acceptable performance. Using this framework may still be possible but would be unlikely to have the same latest features as frameworks since 2021 \cite[AMD Support Page, GitHub Vitis 1.4 Release]{vitis_1_4_support, vitis_1_4_git}.

		% Kinda supported for PYNQ-Z1
		\subsubsection{FINN}
		FINN is a framework specifically for running machine learning models on an FPGA rather than code. It implements a neural network as a series of interconnected streaming layers. A streaming component doesn't run a list of operations like a CPU but instead runs more like a single complex operation. This means that the runtime is not based on a clock speed but instead on the throughput speed (speed at which signals can be sent through the circuit) with a sub-microsecond latency \cite{finn_project, finn_paper}. Almost all machine learning models use too much memory to directly fit on the limited on-chip memory of an FPGA which is why the FINN framework also includes the FINN compiler. The FINN compiler is similar in principle to lossy image compression where through various tuneable compression techniques it reduces the size of a machine learning model while aiming to cause as small of a model performance loss as possible \cite{finn_paper}. In \cite[Getting Started > Supported FPGA Hardware]{finn_docs} the PYNQ-Z1 is listed as retired in favour of larger FPGA boards. Although no longer officially supported the docs explain how it can be re-enabled through a config file and should still work.

		\subsubsection{HLS-4-ML}
		The normal name for this framework is hls4ml, it is a translation framework that sits in the middle of the FPGA ML development pipeline. It accepts a compressed machine learning model file and generates High Level Synthesis (HLS) code \cite{hls4ml_docs}. The outputted HLS code can then be used by most FPGA deployment software (including Vivado HLS and Vitis HLS which can be used for PYNQ-Z1) to create the final logic design for the FPGA \cite{hls4ml_paper, hls4ml_docs}. Vitis HLS is included in the Vitis software platform from \cite{vitis_paper}.

		\subsubsection{Vivado}
		AMD Vivado is not the same kind of framework as above but warrants a section because it is the core software used by the above frameworks to implement designs onto the PYNQ-Z1 FPGA. It is a single vendor design suite that can both be used to create end-to-end FPGA designs itself and also be used to implement HLS from other frameworks \cite{vivado_paper, vivado_paper_2012}.

	\subsection{Compressing Machine Learning Models to FPGA} \label{lit:compression}
	This section covers the compression techniques/tools that are supported by the models in \bcref{lit:models} and frameworks in \bcref{lit:fpga_pipelines}. The Vitis AI framework dropped support for PYNQ-Z1 in 2021 so is likely to be obsolete compared to the other more up-to-date frameworks, therefore it is being excluded as an option. A Python workflow is being explored for the easy high-level machine learning coding large quantity of available libraries. Two common compression techniques are Quantisation and Pruning. Quantisation is scaling high-precision numbers like 64-bit and 32-bit down to lower-precision numbers like 8-bit and 4-bit. This can significantly reduce storage and RAM resource requirements for the ML model. Applied either as QAT (Quantise-Aware Training) and/or as PTQ (Post-Training Quantisation). Pruning is removing redundant or low-impact parts of a machine learning model.
		
		\subsubsection{Compatible with Both FINN and hls4ml}
		PyTorch is a compute library that utilises accelerators like a GPU, including a library for building and training machine learning models \cite{pytorch_paper}. Brevitas is a library used with PyTorch that has features for quantising neural networks during training (QAT) and/or post training (PTQ) \cite{brevitas_src}. It can export the model as a QONNX file which is supported by both FINN and hls4ml.

		\subsubsection{Compression Compatible with FINN}
		FINN provides functions to during compilation to prune parts of the model with thresholds to aid shrinking the model to fit on the FPGA.

		\subsubsection{Compression Compatible with hls4ml}
		Keras is an API for building, training and exporting machine learning models to multiple backends \cite{keras_site}, including PyTorch. Not supported by FINN. Keras includes features for QAT and setting custom bit widths per layer. TFMOT (TensorFlow Model Optimisation Toolkit) is a suite of machine learning optimisation and quantisation features targeting resource-constrained environments \cite{tfmot_paper}, such as ones mentioned in \bcref{lit:hardware}.

	\subsection{Plan for Execution}
	This section explains the workflow steps that will be used for this project. The paper uses the Keras library to implement their SCDNet model, unknown which version of Keras so we will use the latest version Keras 3. A baseline model will be trained without any quantisation that matches the SCDNet parameters, layers and layer shapes as closely as possible. 	\subsection{Dataset Pre-Processing}
		\subsubsection{Dataset Description}
		The ISIC 2019 dataset on the ISIC Archive website is split into separate downloads for training (25,331 images) and test (8,239 images) sets \cite[Data Archive]{isic_2019_download}. The SCDNet paper doesn't mention exactly which downloads they use but they describe the dataset as having exactly the same quantity of images as the training set and splitting that into their training, validation and test sets. Instead both the training and test sets will be downloaded, combined then apply the same ratio of 70\%, 20\%, 10\% for training, testing and validation as the SCDNet paper.

		\subsubsection{Data Processing}
		Following the SCDNet paper to only apply minimal pre-processing: resolution downscaling (400x600 to 224x224), pixel colour normalisation (to 0.0-1.0 float). Both these pre-processing steps will be executed using TensorFlow \cite{tensorflow_paper} to take advantage of GPU acceleration then results saved to SSD for reuse. The model focuses on the 4 target classes of Melanoma (MEL), Melanocytic Nevi (NV), Benign Keratosis (BKL), Basal Cell Carcinoma (BCC)

	\subsection{Baseline Model Training}
	The paper was trained for 50 epochs with a batch size of 20. It also used an SGD (stochastic gradient descent) optimiser to set the initial learning rate to 0.05 then reduce it by 0.1 after 10 epochs along with setting the momentum to 0.8. Keras contains an SGD optimiser class with input arguments for learning rate (including the decay) and momentum. A Keras optimiser is used when compiling the built model. Keras model training is the final step after building and compiling the model class. Only at Keras model training can the number of epochs be set. Batch size is set when using the TensorFlow data loader.

	\subsection{Model Training Using Quantisation and Pruning}
	Applying QAT using either QKeras or TFMOT only requires minor changes to the Keras model building. QKeras swaps layer classes with quantised versions, TFMOT can wrap those layer classes to additionally apply weight pruning. Both QKeras and TFMOT will be adjusted per layer to maximise their effectiveness.

	\subsection{Deploying Quantised Model to PYNQ-Z1}
	The quantised model will not directly run on the PYNQ-Z1 FPGA so will use hls4ml or FINN to deploy the model. The hls4ml framework is directly compatible to export a Keras model to. Using the FINN framework requires a workaround by exporting the Keras model first to QONNX before it can be imported to FINN. Will use hls4ml unless it is not possible to compress the model enough to fit on the PYNQ-Z1 FPGA so try using FINN instead.
