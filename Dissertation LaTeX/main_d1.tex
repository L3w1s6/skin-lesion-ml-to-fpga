	\subsection{Skin Lesion Classification Models} \label{lit:models}
	As a baseline a skin lesion classification model is a type of image classifier machine learning model trained on a skin lesions images dataset to identify the different types of skin lesions present in the dataset. The field of automated skin lesion classification has been greatly boosted this century by developments in machine learning. No single model or method is clearly superior so this section covers some recent popular and successful datasets and model architectures.

		\subsubsection{Popular Datasets}
		As I have learned from my university courses a surprising amount of a machine learning model's performance comes from proper analysis and handling of the training, validation and testing datasets. There are currently nearly 30 public skin lesions datasets available although not all are downloadable without requesting access (paid and free) \cite{survey_datasets_2021, survey_2023}. The most popular datasets I found were Ham10000 \cite{ham_paper, ham_src} and from the International Skin Imaging Collaboration (ISIC) Archive \cite{isic_site}. ISIC  have a large collection of quality controlled datasets and host various ongoing competitions to allow researchers to test performance of their algorithms \cite{isic_site_challenge, isic_site}. Ham10000 served as a training dataset for the ISIC 2018 Challenge \cite{isic_2018_challenge} and has continued to be used to train machine learning models in many papers \cite{survey_2023, survey_general_2023}.

		\subsubsection{Machine Learning Models}
		There are many different skin lesion model papers which all use unique techniques and model architectures. Not all frameworks support all types of models so this subsection focuses on models that are compatible with the frameworks in \bcref{lit:fpga_pipelines}.

	\subsection{Mobile Hardware for Machine Learning Acceleration} \label{lit:hardware}
	Many options for portable hardware exist such as mobile, Nvidia AI accelerators, RPi, embedded FPGAs. This section covers a few popular options including the PYNQ-Z1 I will be using.
	
		\subsubsection{Raspberry Pi 3}
		RPi boards are designed as an embedded System on Chip (SoC) architecture however possess no specialised acceleration hardware beyond what is expected of a modern CPU. I am already familiar with the Raspberry Pi 3 \cite{pi3_product_page}. A cheap (around £30 at time of research) hardware package often used for running lightweight servers and connecting to a vast array of peripherals via a custom Linux operating system. Not known for high performance but has low power usage of only 1.5-4W according to \cite[Section 6]{tess_pi}.

		\subsubsection{Mobile}
		Modern mobile phones have various sensors, cameras and processors designed for general purpose use. For this project only the phone's processor and any AI accelerators would be used so many of the features would be unutilised. This amounts to a larger cost to have access to processors that exist on cheaper and simpler embedded SoC boards.

		\subsubsection{PYNQ-Z1}
		The PYNQ-Z1 is part of a series of boards by Xilinx (now owned by AMD) designed to make running neural networks on FPGAs more easily accessible \cite{pynq_z1_man}. It is an embedded SoC architecture that has an ARM CPU which can run a Linux bootloader similar to a RPi and an embedded Field Programmable Gate Array (FPGA) chip which can be used to create specialised accelerator hardware. Both chips share system resources including RAM \cite[Section 2]{pynq_z1_man}. An FPGA can achieve higher speeds than most accelerators while being programmable, only requiring a few Watts and having limited hardware resources. The PYNQ-Z1 provides a base framework to allow using the FPGA without having to design physical logic circuits. Many frameworks exist to generate efficient and optimised logic circuits which is explored in \bcref{lit:fpga_pipelines}.

	\subsection{Machine Learning Models to FPGA Frameworks} \label{lit:fpga_pipelines}
	This section describes a few of the options for frameworks that could be used to run a skin lesion classification machine learning model on an FPGA.

		% Mentioned as an option but only an old version supports PYNQ-Z1
		\subsubsection{Vitis AI}
		Vitis is a software platform used for digital signal processing and machine learning. The Vitis AI framework is part of the platform and is designed for AI acceleration of CNN models \cite[Page 16, AI Engine Development Environment]{vitis_paper}. A variety of tools and optimisations are included for designing programmable logic focusing on better area compute density and reducing power consumption compared to traditional implementations. It abstracts the programming to C/C++ languages level to allow for easier porting between specific hardware. The current version of Vitis AI is 5.0. The Zynq-7000 family (includes PYNQ-Z1) lost support as of version 1.4 because they were considered to not have enough resources for acceptable performance. Using this framework may still be possible but would be unlikely to have the same latest features as frameworks since 2021 \cite[AMD Support Page, GitHub Vitis 1.4 Release]{vitis_1_4_support, vitis_1_4_git}.

		% Kinda supported for PYNQ-Z1
		\subsubsection{FINN}
		FINN is a framework specifically for running machine learning models on an FPGA rather than code. It implements a neural network as a series of interconnected streaming layers. A streaming component doesn't run a list of operations like a CPU but instead runs more like a single complex operation. This means that the runtime is not based on a clock speed but instead on the throughput speed (speed at which signals can be sent through the circuit) with a sub-microsecond latency \cite{finn_project, finn_paper}. Almost all machine learning models use too much memory to directly fit on the limited on-chip memory of an FPGA which is why the FINN framework also includes the FINN compiler. The FINN compiler is similar in principle to lossy image compression where through various tuneable compression techniques it reduces the size of a machine learning model while aiming to cause as small of a model performance loss as possible \cite{finn_paper}. In \cite[Getting Started > Supported FPGA Hardware]{finn_docs} the PYNQ-Z1 is listed as retired in favour of larger FPGA boards. Although no longer officially supported the docs explain how it can be re-enabled through a config file and should still work.

		\subsubsection{HLS 4 ML}
		The widely used name for this framework is hls4ml, I capitalised it to work as an appropriate title for this subsection. hls4ml is a translation framework that sits in the middle of the FPGA ML development pipeline. It accepts a compressed machine learning model file and generates High Level Synthesis (HLS) code \cite{hls4ml_docs}. The outputted HLS code can then be used by most FPGA deployment software (including Vivado HLS and Vitis HLS which can be used for PYNQ-Z1) to create the final logic design for the FPGA \cite{hls4ml_paper, hls4ml_docs}. Vitis HLS is one of the softwares included in the Vitis software platform from \cite{vitis_paper}. Vivado HLS (cite vivado).

		\subsubsection{Vivado}
		AMD Vivado is not a full FPGA framework but warrants a section because it is the core software used by the above frameworks to implement designs onto the PYNQ-Z1 FPGA. It is a single vendor design suite that can both be used to create end-to-end FPGA designs itself and also be used to implement HLS from other frameworks \cite{vivado_paper, vivado_paper_2012}.
